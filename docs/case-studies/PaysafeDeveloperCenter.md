## Project overview

Following the merger of Skrill and Optimal Payments, I led the documentation work for the launch of the Paysafe Developer Center, bringing payment APIs, SDKs and integration guides from previously separate businesses into a single developer site.

I defined the documentation strategy and information architecture, worked with the web development team on the publishing platform, and authored API and integration documentation, while managing a team of three technical writers.

Paysafe was a rapidly growing business at that time that reported 2016 revenue of just over $1 billion. The Developer Center was highlighted in the company's 2016 Annual Report as one of its achievements under its “State-of-the-art technology” strategy.

## The challenge

* Consolidate hundreds of pages of documentation from previously separate businesses into one developer portal.
* Define an information architecture for multiple payment APIs, SDKs and integration methods.
* Establish a consistent structure for product, integration and reference documentation.
* Create a Git-based documentation workflow with repeatable build, review and publishing processes.
* Migrate existing documentation from the previous Optimal Payments developer centre and Skrill PDF documentation.
* Coordinate documentation across concurrent API, product and platform releases.
* Introduce the writing team to Git, REST APIs and web-development workflows.

## My approach

I reviewed developer portals from PayPal, Braintree and Stripe and used the findings to help define how the new site organised products, guides and API references.

From this research, I designed product landing pages, hierarchical navigation and the overall structure for API, SDK and integration content. I also helped define search requirements and tested the implementation delivered by the web development team.

I worked with Paysafe's web development team to define and test the documentation publishing workflow. Documentation source was maintained in Git and incorporated into a CI-based build process. Builds were published to a staging environment for review before approved content was pushed to the public site using the CMS integration.

As part of this project, I developed migration tooling to move hundreds of pages from the previous Optimal Payments developer centre into the new platform.

Alongside the platform work, I authored API and integration documentation, including API reference material using API Blueprint.

Additionally, I introduced a review workflow using Hypothesis annotations on rendered documentation, allowing reviewers to comment directly on pages rather than reviewing source files in isolation in git.

As Documentation Manager, I managed three technical writers and prioritised work across API documentation, SDK documentation, and platform improvements.

## Deliverables

* The first Paysafe Developer Center.
* Information architecture for API, SDK and integration documentation.
* Product landing pages and hierarchical navigation.
* Git-based source control and documentation review workflow.
* CI-based staging and publishing process.
* Integration with the TYPO3 content-management system.
* Migration tooling for legacy documentation.
* API and integration documentation, including API Blueprint reference material.
* Rendered-page review using Hypothesis annotations.
* Page-level documentation feedback.
* Documentation processes and training for a team of three technical writers.

## Outcome

The first phase of the Developer Center launched in December 2016. Paysafe subsequently included the Developer Center launch in its [2016 Annual Report](https://data.fca.org.uk/artefacts/NSM/data-migration/130622071.pdf) and January 2017 trading update. The launch was also reported in the financial technology press, including [Finextra](https://www.finextra.com/pressarticle/67611/paysafe-expected-to-surpass-1-billion-revenue-milestone-in-fy-2016).
