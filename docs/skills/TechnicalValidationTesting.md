Strong practical experience in **software testing, technical validation, and integration testing**, developed alongside technical-writing responsibilities across financial-services, payments, mobile, and API platforms. Experienced in using testing not only to verify software behaviour, but also to validate documentation, uncover integration issues, identify security concerns, and improve product readiness.

* **Software Testing and QA:** Hands-on experience performing software testing as part of technical-authoring and product-development teams, including taking on dedicated **QA responsibilities for a struggling software project** in addition to documentation duties. Identified, reproduced, documented, and tracked defects in Jira, helping the team move the product towards a stable, releasable state.

* **End-to-End Testing:** Experienced testing complete workflows across multiple system components, including client applications, APIs, backend services, authentication mechanisms, encryption processes, and asynchronous callbacks. Used realistic integration scenarios to verify that systems behaved as documented from the developer or customer perspective.

* **API and Integration Testing:** Built working integrations against **sandbox and production-like environments** using technologies including **Python, Flask, Java, Postman, Curl, and Insomnia**. Used these integrations to verify API behaviour, authentication flows, encryption, error handling, webhooks, and documentation accuracy.

* **Black-Box Testing:** Experienced validating applications and APIs from an external user or integrator perspective without relying on implementation details. Tested inputs, outputs, error conditions, workflows, and edge cases to identify discrepancies between expected and actual behaviour.

* **Component Testing:** Tested individual APIs, services, application features, and integration components independently before validating them as part of larger end-to-end workflows.

* **Smoke and Release Testing:** Performed focused testing of critical functionality following builds, fixes, or configuration changes to identify blocking defects quickly and establish whether software was sufficiently stable for more detailed testing or release.

* **Usability Testing:** Evaluated software, developer tools, documentation platforms, and integration workflows from the user perspective, identifying confusing behaviour, workflow friction, unclear error messages, and opportunities to improve usability and developer experience.

* **Documentation Validation:** Routinely tested documented procedures, code samples, API calls, authentication instructions, and integration workflows rather than assuming existing documentation or specifications were correct. Used findings to correct both software-related issues and documentation defects.

* **Detailed Defect Reporting:** Experienced producing clear, actionable **bug reports for engineering teams**, including reproduction steps, expected versus actual behaviour, environmental information, supporting evidence, severity or impact, and relevant technical observations.

* **Jira-Based Defect Management:** Raised and tracked defects through **Jira**, worked with developers to clarify issues, retested fixes, and contributed to prioritisation based on severity, customer impact, security implications, and release readiness.

* **Security-Focused Testing:** Treated potential **security defects as priority issues**, escalating concerns where application or API behaviour could expose credentials, sensitive information, authentication weaknesses, encryption problems, or other security risks.

* **Sandbox vs Production Validation:** Strong understanding that sandbox environments do not always replicate production behaviour exactly. Experienced identifying **sandbox limitations, mocked behaviour, test-data constraints, configuration differences, and integration assumptions** that could affect the accuracy of testing or developer documentation.

* **Testing Across Restricted Corporate Environments:** Experienced troubleshooting practical integration-testing challenges including **corporate firewalls, proxy restrictions, network access controls, callback accessibility, and externally initiated webhook traffic**.

* **Cloud-Based Integration Testing:** Used externally hosted and cloud-based environments to overcome internal network restrictions and test integrations that required public accessibility. At Mastercard, created cloud-hosted encryption/decryption and webhook integrations to validate real API and asynchronous processing behaviour.

* **Test Automation and Reusable Test Integrations:** Developed scripts, sample applications, and reusable integration code to make repeated API and documentation validation more efficient. Used programming skills to investigate behaviour beyond what could be established through manual testing alone.

* **Testing as Part of Technical Writing:** Applied a test-driven approach to developer documentation, using working software and integration code to verify technical claims before publication. This approach helped uncover undocumented behaviour, incomplete integration guidance, authentication and encryption issues, and inconsistencies between specifications and real system behaviour.
